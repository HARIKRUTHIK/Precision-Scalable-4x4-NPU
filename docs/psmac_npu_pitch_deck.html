The Atom — SBB (Simple Bit Brick) Module 1
Speaker 1
Think of the SBB as the tiniest LEGO brick in our entire design.
Every multiplication your phone does — at the very bottom, deep inside the chip — boils down to multiplying two tiny 2-bit numbers. That's exactly what the SBB does.
We built it from scratch, gate by gate — AND gates, Half Adders, Full Adders — using a mathematical technique called Baugh-Wooley that handles negative numbers correctly in binary.
Most engineers would just type a "*" in their code and let the tool figure it out. We didn't. We manually wired every gate because we wanted to remove one Full Adder and one AND gate that the standard approach wastes. Less gates = less power = less silicon area. At the atomic level, every gate saved matters.
"It's like building a car engine by hand, bolt by bolt, instead of ordering a pre-assembled one — because you know exactly which bolts you don't need."
3
The Building Block — BBU (Bit Brick Unit) Module 2
Speaker 1
Four SBBs working together — and smart enough to change their job based on the mode.
The BBU takes two 4-bit numbers and multiplies them. It does this by splitting each number in half — a top half and a bottom half — and using four SBBs to multiply all the combinations.
Here's the clever part: the BBU uses Karatsuba decomposition. Instead of doing four separate multiplications and adding them up one by one, it rearranges the math so the cross-terms collapse into one operation. It's a shortcut that mathematicians figured out in the 1960s that we've now implemented in hardware.
In INT2 mode: the BBU says "forget combining, just give me four independent small products packed side by side." That's how you get 4 results for the price of 1 memory read.
In INT4/INT8 mode: it fuses those products into one proper 11-bit result.
"Same hardware, different personality depending on what you ask of it."
4
The Multiplier Brain — RFU (Recursive Fusion Unit) Module 3
Speaker 2
Four BBUs under one roof — the full 8-bit multiplier that drives everything.
The RFU does the same trick the BBU did, but now at the 8-bit level. It splits two 8-bit numbers into nibbles and uses four BBUs — one for each nibble combination.
The output is an 80-bit wide bus — and depending on the mode, those 80 bits mean completely different things:
INT8 mode
One 16-bit result sits in the first 16 bits. 64 bits unused.
INT4 mode
Four 11-bit results packed back-to-back. 2× the data per read.
INT2 mode
16 independent 5-bit products fill all 80 bits. 4× throughput.
And the best part: the RFU is fully combinational — no clock, no wait. You put numbers in, the answer comes out in the same clock cycle. Pure speed.
5
The Memory — weight_mem Module 4
Speaker 2
Where the numbers live before the math begins.
Every MAC tile needs to store two things: the weights (the learned knowledge of the neural network — these stay fixed per inference) and the input activations (the data coming in — changes every time).
We store both in two separate 256-byte memory arrays. They share a single address line driven by the FSM — so with one address, you get both numbers simultaneously.
Critical design decision: reads are asynchronous. That means the moment the FSM sets an address, the data is available immediately — no waiting for the next clock edge. This saved us an entire pipeline stage, which directly improves our clock speed.
"Like opening a book and seeing the page instantly — no page-turning delay."
6
The Brain — FSM (Finite State Machine) Module 5
Speaker 3
The conductor that keeps everything in sync.
The FSM is like a stage director. It tells every other block when to start, when to run, and when they're done. It has four states:
IDLE
Waiting for a "go" signal.
CLEAR
Wipes the accumulator clean before starting fresh.
RUN
Steps through memory addresses one by one, feeding data to the pipeline. Runs for N cycles.
DONE
Signals that the result is ready and valid.
Smart precision-aware scheduling: in INT8 mode it runs for N steps. In INT4, it runs for N/2 steps — because each memory read produces 2 products. In INT2, only N/4 steps needed. Automatic throughput scaling built into the control logic.
7
The Pipeline — pipe_reg & Accumulator Module 6 & 7
Speaker 3
The timing glue that makes everything run at 40 MHz without errors.
pipe_reg is an 80-bit register sitting between the RFU and the accumulator. Its job: break up the long chain of combinational logic so the chip can run faster. Without it, signals would have to travel too far in one clock cycle and the design would fail at high speeds.
Think of it like a relay race — instead of one runner doing the whole track, two runners each do half. The total time is the same or less, but each runner can sprint.
Accumulator adds up products cycle by cycle into a running 32-bit total. It knows the precision mode and sign-extends correctly for INT2, INT4, or INT8. It also has a critical fix: acc_en is delayed by one clock to stay aligned with the pipeline stage — without this, the first result would be garbage.
"This is the kind of subtle bug that kills projects in the final hour. We caught it, fixed it, and built the delay register deliberately."
8
One Complete Tile — psmac_top Module 8
Speaker 4
All six blocks wired together into one working compute tile.
psmac_top is the full package: memory + multiply + pipeline + accumulate + control, all in one module. It takes in two vectors, computes their dot product, and outputs a 32-bit result with an out_valid flag when done.
The data flow inside one tile, every clock cycle:
FSM drives addr → weight_mem reads x & w (same cycle) → RFU multiplies (same cycle) → pipe_reg latches → accumulator adds → result ready
This is a 2-stage pipeline. While the accumulator is adding last cycle's product, the RFU is already computing this cycle's product. Overlap = efficiency.
9
The Full Array — npu_4_4 & npu_ctrl Module 9 & 10
Speaker 4
16 tiles working in parallel — a real matrix multiplier.
npu_4_4 is a 4×4 grid of 16 psmac_top tiles. Each tile computes one output of the matrix multiplication Y = W × X. All 16 run simultaneously — so a full matrix multiply takes the same time as a single dot product.
npu_ctrl is the top-level choreographer. It automates the entire inference cycle through 5 states:
IDLE
Wait for start signal
LOAD_W
Fill all 16 weight memories
LOAD_X
Broadcast inputs column by column
RUN
Trigger all 16 MACs at once
COLLECT
Gather results via selector mux
out_valid only goes high when all 16 tiles have finished — it's the AND of 16 individual valid signals. No tile left behind.
